# Writing style

These rules come from how the user rewrites drafts. Follow them exactly.

## Voice

- Write complete sentences with a subject and a verb, in slightly formal, precise wording. Prefer "detailing how" to "meaning how", and "organized into three categories" to "they fall into three groups".
- Write in a storytelling manner: each page reads as a short narrative, not a spec sheet.
- Lead with what is most interesting about the work: what it does differently, and its results.
- Keep the tone fair and neutral. No paper is the reference point.

## Format

- Keep paragraphs short, at most 3 sentences, and break them up with figures.
- Use bullet points only for genuine lists, never in place of prose.
- Write numbered points (gaps, ideas) as one paragraph each, starting `1\)`, `2\)`, with a lowercase word after the number. Introduce them with a lead-in that ends in a colon ("…there are still several gaps, like:" / "…we might want to look into:"). The backslash stops Markdown and Notion from turning them into ordered lists.
- In the hub README, entries follow the same chronological, categorized order as the pages.

## Never

- Tables.
- Callout or admonition boxes.
- "TL;DR:" labels or sentences that start with a fragment.
- Em dashes. Use commas, colons or parentheses instead, and use them sparingly.
- Arrows (→) in prose. Write "rises from 26% to 84%".
- Meta commentary about the document itself ("this page covers…", "each page uses the same structure…").
- Scaffolding in prose, such as item ranges like "(1 to 10)".

## Numbers

- Use only numbers from the paper, project page or repo, and say "not reported" when a figure is missing.
- State the protocol whenever it matters: self-evaluated, a subset, privileged state, demos, practice runs or a larger budget.
- When two papers' numbers are not comparable, say so instead of comparing them.
